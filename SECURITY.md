# Security policy

## Supported version

Security fixes are applied to the latest `main` branch during active development.

## Reporting

Do not disclose vulnerabilities, secrets, or applicant data in a public GitHub issue. Contact the repository owner privately through the security contact configured on the GitHub repository. Include reproduction steps, affected endpoints, impact, and suggested remediation when possible.

If a credential is exposed, revoke and replace it immediately before investigating Git history or logs.

## Scope

Reports concerning authentication bypass, recruiter tenant isolation, resume access, workflow approval authorization, injection, unsafe file parsing, secret exposure, and dependency vulnerabilities are especially important.
